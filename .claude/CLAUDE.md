# The project: Building a chatbot and possible MCP server for PLATO Pub

## Background
The PLATO pub website https://platopub.phys.au.dk/about/platopub.php , led by Mikkel Lund and hosted at Aarhus University provides information about the PLATO space telescope.  PLATO is being build by a large consortium and will probably launch late 2026 or early 2027. For the website all publications about PLATO are collected in one place: https://platopub.phys.au.dk/about/ads_feed.php . Currently these are papers about the development and expected capabilities of PLATO. Once the telescope becomes operational, this will shift towards papers presenting results from PLATO observations.

In this project we will make the information from the PLATO publications available through a chatbot, and possibly also an MCP server. The goal is to encourage and facilitate researchers' use of PLATO data for high quality, impactful results, by reducing the time and effort they need to spend on understanding the technical details of the instrument and data. This way they can focus on the science.

## Repository layout

The whole PlatoPub folder is one git repo (remote: hireck/platochat, private).

* `platochat/` — the chatbot itself: `plato_core.py` (the UI-agnostic core), `plato_api.py` (the FastAPI backend), `plato_chat.py` (the Streamlit UI), and `.env` with the API keys
* `ingest/` — everything that turns papers into indexed chunks. `update_corpus.py` runs the whole ingest, doing only what is not done yet (`make update`; `cron_update.sh` is the wrapper for running it nightly from cron). The steps: `fetch_metadata.py` (the PLATO-Pub list plus full ADS metadata, written to `papers.json`), `fetch_fulltext.py` (downloads the full texts we may use: arXiv source, arXiv PDF, open-access PDFs — never paywalled ones), `fetch_licences.py` (records in the manifest under what licence each paper, and the copy of it we indexed, is published), `latexml_to_markdown.py` and `pdf_to_markdown.py` (source to markdown), `heading_levels.py` (repairing the heading levels marker gets wrong), `textsplitter.py` (chunking), `reindex_weaviate.py` (the Weaviate objects, their fingerprints and the schema; run on its own, `make reindex`, it rebuilds a collection from scratch), `paper_index.py` (the whole-paper index, `<collection>_PAPERS`; `make papers`), `esa_site.py` (crawls ESA's PLATO website into `PLATO_ESA_SITE`; `make website`), plus the paper metadata JSONs — `papers.json` is the current one; `PLATOChat_papers.json` and `present_papers.json` are from March 2024 and only still used by the older scripts. `get_present_papers.py` and `chunk_tex_data_plato.py` are older code from the FAISS days, kept for reference for their markdown and chunking heuristics — the FAISS index itself and the cells that built and queried it are gone; they still expect to be run from the data directory rather than from the repo.
* `eval/` — `questions.json` (47 questions -- 4 of them, category `papers`, about the papers themselves and scored in retrieval mode through `find_papers` with the arguments they carry -- with the paper(s) that should answer each, and patterns the answer must contain; the papers were extended to the 179-paper corpus on 2026-09-22 -- a paper is listed when its indexed text answers the question, found by text search over the index and then read, and a paper giving an outdated value is named in the note instead) and `run_eval.py`, which scores retrieval alone (`make eval`, ~1 min, no LLM) or whole answers (`make eval-full`, ~10 min, needs the AU network). Run it before and after anything that touches retrieval, chunking or the prompts. Results land in `eval/results/` (not tracked). `compare_runs.py` pools several full runs per model configuration and sets them side by side -- checks, where the time went, tool use, empty replies, citations of passages never given -- for when the AI Lab changes its models (GLM-5.3-Flash was compared this way on 2026-09-28 and not adopted; see the comment on `ANSWER_MODEL` in `plato_core.py`). Run the configurations at the same time, a few runs each: one run differs from the next by a check or two.
* `local_site/` — a local copy of the PLATO Pub pages, for developing the chatbot front-end against
* `Makefile` — the dev runner: `make dev` starts the API and the static site together, `make update` brings the corpus and the index up to date, `make status` shows which papers have full text and what failed, `make licences` reports their licences, `make metadata` refreshes `papers.json` alone, `make reindex` rebuilds the Weaviate collection from scratch, `make papers` updates the whole-paper index alone, `make website` re-crawls the ESA website alone, `make eval` runs the evaluation

## The chatbot

The PLATO chatbot shall be part of the PLAT Pub website. We'll probably want to run it in a docker.

### Information sources

* platochat_info.md: a short document with high level information about PLATO (from the website, maybe pull it from ther directly in future?) and about the chatbot itself
* a full-text RAG index with hybrid retrieval on chunks to answer detailed questions. 
* a whole-paper level index that lets users search papers by metadata, like author names and publication date

The whole-paper index (built 2026-09-24): `ingest/paper_index.py` keeps one Weaviate object per paper in `<chunk collection>_PAPERS` (`PLATO_PAPERS`, `PLATO_NEXT_PAPERS`; `PLATO_PAPER_COLLECTION` overrides) -- title, abstract and ADS keywords, searched by bge-m3 vector and BM25; authors and year, filtered on. The answering model reaches it through a second tool, `find_papers(query, author, first_author_only, year_from, year_to, limit)`, next to `search_publications`; both share the `FOLLOWUP_SEARCHES` budget. The router is unchanged: it still runs only a passage search, and the system prompt (`FIND_PAPERS_INSTRUCTIONS`) tells the model that author and date questions need `find_papers` even when passages were given. With a query, papers are reranked on title + abstract with the same cross-encoder and threshold as the chunks (checked on six topics: on-topic papers score 0.5-1.0, the rest below 0.4); without one, every paper matching the filters is listed newest first. The tool reports how many papers match, so the model can say "37 papers, here are ten". Paper records are numbered and cited like passages, and show in the Sources panel as "Section: Abstract". Each record says what the chunk index holds of the paper (`indexed`: full text / abstract only), read from the chunk collection itself, which is also why a paper not yet in the chunks is left out here.

Author matching: ADS writes "Surname, Given". Surnames are folded to plain ASCII (`Català` = `Catala`, `Jørgen` -> `jorgen`) and every run of words of a compound surname is its own exact key, so `Aguirre Børsen-Koch` is found by `Børsen-Koch`, `Koch` or `Aguirre` (ADS itself has both "Collier Cameron" and "Collier-Cameron"); a lone particle (`de`, `van`) is not a key. Exact keys rather than Weaviate's word tokenizer so that `Lund` never finds `Lundkvist`. An author given with first names ("Mikkel Lund") matches nothing whole, and then its last word is tried. `fold_name()` in `paper_index.py` and `author_key()` in `plato_core.py` must stay in step. `make update` and `make reindex` keep the paper index up to date (only records whose fingerprint changed are embedded; about 17 s for all 178 from scratch).
* ESA's PLATO website, for the practical side: calls for proposals, proposal tools, data access (see below)

ESA's PLATO website (built 2026-09-29): `ingest/esa_site.py` crawls every page under https://www.cosmos.esa.int/web/plato/ (one request a second; no robots.txt rules) into its own collection, `PLATO_ESA_SITE` (`PLATO_SITE_COLLECTION` overrides) -- not tied to the chunk collection's name, since the site has nothing to do with the paper list. It runs as the fifth stage of `make update` (so nightly under cron) and alone as `make website`; each run's markdown is kept in `<data>/esa_site/`. Page text comes from Liferay's `journal-content-article` blocks, converted by pandoc; the news page's cards become a dated list. A block on more than half of the pages is boilerplate (the helpdesk footer, on 52 of 55) and dropped, after its "This website was last updated on ..." date is read. Pages served under several addresses (plato-arxiv / plato-archive / plato-arxive, observations / observation-concept, first-observation-field / first-sky-field) are kept once, under the address found first from the home page. First crawl: 52 pages, 48 with text, 291 passages. Chunked and fingerprinted like the papers; the dates (`checked`, the day the text was last seen; `site_updated`) are patched in place every run without re-embedding. A page that fails to load keeps its passages; a crawl that loses more than half the pages removes none. The linked documents (AO-1 call, Policies & Procedures, Mission Handbook, Product Definition Document, CHS/CfP user manual) are not indexed -- the pages link to them and the model passes the links on.

The answering model reaches it through a third tool, `search_esa_website(query)`, sharing the `FOLLOWUP_SEARCHES` budget; the router is unchanged, as for `find_papers` (its first search always goes to the papers), and `SITE_TOOL_INSTRUCTIONS` tells the model to use the website for practical questions even when passages were given, to prefer it over the papers on those matters, to defer to the Policies & Procedures document for a call's binding rules, and to send what the site does not answer to the PLATO Helpdesk. Website passages are shown to the model with `source: ESA PLATO website`, the page, its URL and `checked`, and in the Sources panel as "ESA PLATO website: *[page](url)*, checked <date>". In the eval a page is a source named `esa:<page>`; the eight `website` questions are scored in retrieval mode through the website index.

Important: older information can be outdated. The publication date of retrieved information needs to always be made available, and the chatbot needs to be instructed to prefer more recent information.

How this is done: every chunk carries its paper's `pubdate` (from ADS); the model sees it in each passage's metadata and the system prompt tells it to go with the most recent passage where they disagree and to say so; the Sources panel shows the year and month and links each title to its ADS page (plus publisher and arXiv links). Deliberately *not* done: boosting recent chunks in the ranking, which would bury the definitive older paper on questions where age is irrelevant. The `recency` questions in the eval set (camera count, field of view, launch date — all of which changed between the 2014 and the current design) are there to show whether the prompt alone is enough.

General knowledge (decided 2026-09-21): the papers come first, but an astronomy-related question they do not cover may be answered from the LLM's general knowledge, **provided it is flagged to the user**. The system prompt makes the model say that the publications do not cover the point and put the general-knowledge part in its own paragraph under a fixed label (`GENERAL_KNOWLEDGE_LABEL` in `plato_core.py`: "General knowledge, not from the PLATO publications"), without citations. The wording is fixed rather than left to the model so that users learn to recognise it and the eval can check for it, in both directions: present where it should be (`expect_flag: true`), absent from answers the papers fully support (`expect_flag: false`). Questions unrelated to astronomy or PLATO are declined. The label matters most for facts about PLATO itself, where the model's training data can be years behind the papers.

Passage ids: chunks are stored under a stable `chunk_id` (`<bibcode>#0017`, position within the paper) so that adding or removing a paper does not renumber the rest. The model never sees those; it cites passages by their position in the current request (1, 2, 3, ...), which is easier for it to copy correctly.

Figures: We want to have the option to have figures from the paper displayed if they seem relevant for the answer, based on the caption and/or the mention of the figure in the cited text. (Extracting information from images directly is not a priority.)

### Data ingestion

The papers are listed on https://platopub.phys.au.dk/about/ads_feed.php . That page is an empty shell filled by JavaScript from a JSON endpoint, `https://platopub.phys.au.dk/about/ads_middleware.php?page=1&rows=1000&year=&author=&keywords=`, which is what `fetch_metadata.py` reads — no HTML scraping. The list is itself an ADS query (published papers only, i.e. no arXiv-only bibcodes; "PLATO" in title and abstract; "space" in the full text) and shows a "last updated" date of the same day, so it appears to refresh daily. Being a name search, it also catches other PLATOs: Yang et al. 2009 (PASP) is about PLATO, the site-testing observatory at Dome A in Antarctica. `OFF_TOPIC` in `fetch_metadata.py` keeps such papers out of the corpus, with the reason (the user's call, 2026-09-24); Mikkel may want it off the list itself.

Bibcodes are not permanent: a preprint (`2024arXiv240104503D`) or an early-access paper (`2026MNRAS.tmp.1093M`) gets a new bibcode on publication, and the list can briefly carry both. ADS keeps the old ones as aliases of the new record, and `papers.json` stores them under `aliases`. `reindex_weaviate.py` uses those to match a markdown file converted under an old bibcode to the paper's current record; a markdown file that matches nothing is not on the list and is left out of the index.

The arXiv source bundle can contain more than one compilable `.tex` file: for Bray et al. 2023 the MNRAS author guide (`mnras_guide.tex`) was converted in place of the paper, and its chunks sat in the index under the paper's name until the eval caught it. Whatever picks the main file in the future pipeline must not just take the first `.tex` with a `\documentclass`. As a backstop, `reindex_weaviate.py` refuses a markdown file that does not contain its own paper's title.

LaTeXML evaluates `\today` at conversion time, so A&A papers carry the conversion date in their front matter — "(June 21, 2026)" on a 2019 paper. Now that the model is told to weigh publication dates, that is a false date sitting in the text. Fixed 2026-09-21 in two places, both through `strip_false_dates()` in `latexml_to_markdown.py`: the converter removes a front-matter date line that falls within its own run (a range, not "today" — PlatoSim's conversion crossed midnight), and `reindex_weaviate.py` removes one dated more than a month after the paper's ADS publication date, which covers markdown converted before the fix (four A&A papers) without editing the files. MNRAS papers had a second false date, "pubyear: 2015" on a 2021 paper — template debris LaTeXML leaves in the keyword block; it went when keyword blocks were dropped from the index.

LaTeXML writes "Abstract", "Key Words.:" and "Acknowledgements." as level-6 headings, so the chunker splits on all six levels. Before it did (it stopped at five), abstract chunks had no section name — the Sources line fell back to raw chunk text, which is how the false date surfaced in a citation — and the acknowledgements of 15 papers were indexed as the tail of their last section instead of being dropped. Keyword blocks are dropped on purpose: as chunks of their own they are bare term lists a dozen tokens long, which BM25's preference for short documents would rank highly for any query sharing a term.

Their complete metadata is then to be collected via the ADS link. There is an ADS_API_KEY in platochat/.env . There was some old code that yielded /Users/hilke/data/plato_data/OneDrive_1_11-03-2024/PLATOChat_papers.json, but this did not include publication dates, and possibly some other fields are missing as well. We want to collect all the available information.

For papers that have an arxiv ID: If the latex source is available, we will process that (ingest/latexml_to_markdown.py), otherwise we will use marker to process the pdf (ingest/pdf_to_markdown.py).

We compared marker against MinerU on two PLATO papers (2026-09-20). Text quality is close — MinerU is somewhat faster and finds a few more figures — but we went with marker for operational reasons: MinerU 4.x is a client/server tool that defaults to sending PDFs to mineru.net (local parsing is `disabled` out of the box and needs a running server plus its own model download), it silently converts only the first 10 pages unless told otherwise, and it no longer writes image files at all — figures come back as opaque locators into its internal library. marker stays a plain in-process Python call that writes the figures beside the markdown. `pdf_to_markdown_mineru()` is kept for reference but is written against the MinerU 2.x CLI and will not run against 4.x.

marker's weak point is that it assigns heading levels almost arbitrarily, which corrupts the section breadcrumbs textsplitter builds. ingest/heading_levels.py rebuilds them from the section numbering and runs by default inside pdf_to_markdown().

Page furniture (running headers, footers, publisher stamps) needs no filter for now. Checked on seven papers (~200 pages, five publishers: ExA, EPJ Web of Conferences, A&A, SPIE, MNRAS): marker's layout model discards it on its own, and across 3046 lines exactly one instance survived — a venue heading, "EPJ Web of Conferences" on Ouazzani et al. 2015. Nothing leaked into body text. A filter was written and dropped again, because a rule fitted to one example is not evidence it would catch whatever turns up next. **Re-check this once the corpus is larger**, and fit any filter to what is actually found then.

Two things worth keeping from that exercise. First, the obvious heuristics are all dangerous and were each caught destroying real content: "a heading with nothing under it is furniture" flags every section opening with a subsection ("2. Modelling strategy" then "2.1. Seismic inversions"); "a bare number line is a page number" flags the wrapped page field of a citation ("... 2012, MNRAS, 425," / "757"); "a line naming a journal is furniture" flags bibliographies — all 240 journal-abbreviation hits in one paper were citations. Any future filter must leave everything from the references heading onward alone. Second, ADS stores the expanded journal name ("European Physical Journal Web of Conferences") while PDFs print the abbreviation ("EPJ Web of Conferences"), so matching a venue name needs overlapping words, not a substring test. The dropped implementation is kept at the git tag `experiment/page-furniture` (`git show experiment/page-furniture`).

Papers that are not on arxiv often have a link to for example the publisher's page where the paper can be downloaded. This will typically be pdf, or maybe html in some cases. We will need to confirm which formats the papers are in, and figure out how we can automatically download them. Typically we will need to find the download link on the page. Some of these papers will be pay-walled. Typically, the university has access to these papers, as they pay for them through a deal with the publisher. And users will typically have access too, through their own university. The chatbot will provide links to the original papers in their original location. Unpublished materials, such as internal documents will not be included. The chatbot will be public facing.

Decided 2026-09-21: full text only for papers on arXiv or flagged open access by ADS; the paywalled ones are indexed by their abstract. See "Keeping the corpus up to date" below.

Once the chatbot is up and running, its sources will need to be kept up-to-date. The PLATO Pub list will need to be regularly checked for new papers. (I'll need to check with Mikkel with what frequency the list is updated.) When new papers appear, they need to be processed and added to the chunk index and whole-paper index. The original documents (pdf/latex/html) and the full markdown do not need to remain saved on the server, once processing is complete.

This is `make update` now, meant to run nightly from cron (see below).

Papers that are dropped from the list (e.g. arxiv-only preprints that have been replaced with their published version) should ideally also be dropped from the index.

### Keeping the corpus up to date

Built 2026-09-21. `make update` (`ingest/update_corpus.py`) does the whole ingest and only what is not done yet: it refreshes `papers.json`, downloads and converts the full texts that are missing, then writes the Weaviate objects of papers that are new or changed and deletes those of papers that left the list. `ingest/cron_update.sh` wraps it for cron: it sets a PATH that finds LaTeXML, pandoc and Ghostscript, points `PLATO_MARKER_PYTHON` at marker, and appends everything to `<data>/logs/update-YYYY-MM.log`. It exits non-zero only when the list could not be refreshed or the index not updated. It is not installed as a cron job anywhere yet; that belongs on the server. `make status` summarises where every paper stands.

**Full text only where we may share it** (decided 2026-09-21). Papers on arXiv or flagged open access by ADS get their full text indexed: 85 of the 179 (49 arXiv, 36 open access elsewhere). Every other paper is indexed by its ADS abstract alone, as one object with `coverage: abstract only`, so that every paper on the list can be found. Downloading the paywalled ones would be easy (on the AU network the publishers serve them), but quoting subscription content in a public chatbot is redistribution. The rule is `fetch_fulltext.fulltext_sources()`; it is enforced again at indexing time and for PDFs saved by hand. Note that ADS's "open access" means free to read, not an open licence -- the same footing as arXiv, fine for short attributed quotations. The system prompt tells the model what `coverage: abstract only` means (an abstract does not show what a paper leaves out), and `platochat_info.md` tells users. A full text whose markdown lost its abstract gets the ADS abstract added as an extra object (checked by five-word sequences: 0.64-1.00 of them found with the abstract present, 0.01-0.21 with it cut out).

**Licences** (recorded 2026-09-22; deciding what is indexed since 2026-09-24). Free to read is not free to share, so `fetch_licences.py` (the "licences" step of `make update`; `make licences` prints the report) records per paper -- looked up when the paper is new, and again only when ADS reports something new about it (arXiv id, DOI, link, open-access flag); no periodic recheck, the user's choice, so `--recheck-licences` is the way to catch a licence that changed on its own -- in the manifest under `licence`, the licence of the copy we indexed and of the published version: arXiv's licence from its OAI-PMH record (arXiv's search API does not carry it), Crossref and DataCite for what the publisher deposited with the DOI, OpenAlex for its reading of the landing page ("bronze" = free to read, no licence). Where those sources overlap they never disagreed. The ADS `copyright` field is no substitute: it is not a licence and describes the publisher's version (Wiley's generic line sits on two papers Crossref says are CC BY). Nor is the paper itself: no licence statement survives in the text layer of the 32 downloaded PDFs or in any markdown (marker drops page footers). Of the 78 full texts: **32 openly licensed** (CC BY, one CC BY-SA, one public domain), **4 CC BY-NC-SA or -NC-ND** (arXiv choices; fine for a free non-commercial service), **42 with no licence** beyond reading -- 55% of the full-text objects: 17 arXiv preprints under arXiv's default licence whose *published* version is CC BY (Rauer 2025, Samadi 2019, Börner 2024 ...), 8 arXiv preprints with no open version anywhere (Montalto 2021 asPIC, Marcos-Arenal 2014 PlatoSim, Rauer 2014, Grenfell 2020, de Almeida 2020, Morris 2020, Cunha 2021, Veras 2015), and 17 publisher copies with none (the 2006-2013 proceedings and ADS scans, IAU symposia, PASP 2009, EPSC, SF2A, JBAA, The Observatory, the Porto thesis). What dropping them would cost was measured on side collections in which those papers keep only their abstract (`PLATO_LIC_STRICT`: all 42; `PLATO_LIC_LENIENT`: the 25 with no open version): answers still contained the expected facts as often as on `PLATO_NEXT` (34/35 in each; two runs on `PLATO_NEXT` gave 34 and 33), because abstracts state the headline numbers and other papers repeat them; what goes is the detail and the caveats in the body (hare-and-hounds lost its per-method error ranges, the noise-floor answer lost "this is a lower limit"), and in the strict case 3 answers no longer cite the paper the question was written about. The eval's patterns test headline facts, so they understate this.

**The rule** (the user's, 2026-09-24): what matters is not the licence as such but whether a *publisher* could complain. A copy the authors put in the open themselves -- an arXiv preprint, a thesis in a university repository -- is indexed whatever its licence, because only the authors could object and a paper a chatbot cites gains readers; a publisher's own copy (its PDF, ADS's scan of the printed pages) only where the publisher published it under an open licence. That is `fetch_licences.indexable()`; `allowed_sources()` applies it one step earlier so such a copy is not downloaded and converted in the first place, which is why the licences step runs *before* the fetch. Of the 78 full texts held, 62 are indexed and 16 are left out (183 objects, 3% of the words: the 2006-2013 proceedings and ADS scans, the IAU symposium papers, EPSC, SF2A, JBAA, The Observatory) -- indexed by their abstract like the paywalled ones, state `not indexable` in the manifest. The 8 arXiv preprints whose published version is not open (Montalto 2021 asPIC, Marcos-Arenal 2014 PlatoSim ...) stay, by the same rule. Side findings: 4 papers indexed by abstract are CC BY at the publisher (three are the open-access downloads refused by EPJ, IOP and OUP -- a hand-saved PDF is clearly fine; 2020EPSC...14...40G is outside the access rule because ADS does not flag it open); 59 of the 60 SPIE papers carry ADS's note "Downloading of the abstract is permitted for personal use only" -- their abstracts stay in the index while Mikkel is asked about them.

**Where full texts come from**, best first: a PDF saved by hand as `<data>/manual/<bibcode>.pdf`; the arXiv LaTeX (LaTeXML); the arXiv PDF (marker); the publisher's PDF (the link from the ADS resolver, else the `citation_pdf_url` tag on the landing page, which is how Zenodo and Cambridge work); an author's copy; ADS's scan of the printed pages. A permanent failure (404, 403, a conversion that fails its checks) moves on to the next source; a temporary one (timeout, 5xx, a bot check, arXiv refusing us) waits for the next round or the next run, and counts as permanent after 10 in a row (`MAX_TRANSIENT_TRIES`). What does not download automatically, and why: Oxford University Press (MNRAS) and EPJ answer 403 to scripts, Springer serves a JavaScript bot check, IOP sometimes does (Radware, validate.perfdrive.com; the same PDF came through in the morning), the links of the 2015 Spanish proceedings (sea-astronomia.es) are dead, and the ASP pages name no PDF. Publisher refusals are respected, never worked around: `make status` lists those papers with their ADS links, and a PDF saved by hand into `<data>/manual/` is taken up on the next run.

arXiv's CDN refuses Python's built-in HTTP client (urllib) with an empty 406 on most requests for uncached files, while curl and the `requests` library are served (measured 2026-09-21, and widely reported that year). arXiv's published rules invite programmatic downloads from export.arxiv.org at up to four requests a second, so arXiv is fetched with `requests`, five seconds apart, with an honest User-Agent. Other hosts keep urllib.

**The manifest** (`<data>/manifest.json`) holds, per paper: the access class, the allowed sources, the last outcome of each source tried, where the full text came from (URL, file, hash, converter) and where its markdown is. It decides what gets downloaded and converted; a failed paper is only tried again when ADS reports something new about it (a new arXiv id, an open-access flag, a new link), when a PDF appears in `manual/`, or with `--retry-failed`. `make update UPDATE_ARGS="--only <bibcode> --redo"` puts one paper through again. On its first run it took over the 27 papers converted before it existed ("adopted").

**What is indexed is read from Weaviate, not from the manifest.** Every object carries a `fingerprint`: a hash of its markdown, the paper's metadata, the chunk settings and `INDEX_VERSION`. A paper is rewritten only when its fingerprint changes, so a lost or rebuilt collection (the local Weaviate has no volume) is repaired by the next `make update` without downloading anything, and `make reindex` and `make update` produce identical objects (checked: same UUIDs, same content). Bump `INDEX_VERSION` in `reindex_weaviate.py` when changing chunking code; that re-indexes every paper. Replacing a paper writes the new objects first (UUIDs derive from `chunk_id`, so a write replaces) and deletes the leftovers after, so the paper is never missing; if interrupted, the next run finishes the job. Safety catches: a list that loses more than 10 papers at once is taken for a broken feed (`papers.json` is kept; `--allow-removals` overrides), and a lock file allows one run at a time.

First run, 2026-09-21: 78 of the 85 papers that may have full text got it (27 taken over, 19 arXiv LaTeX, 3 arXiv PDFs, 20 publisher PDFs, 8 ADS scans, 1 author copy -- 87 minutes on the Mac); the 7 others are the refusals and dead links listed above. The collection holds 5035 objects for 179 papers. Two lessons from it: LaTeXML takes 10-15 minutes per stage on papers whose packages load the LaTeX3 kernel (`derivative.sty`, for one), so conversions run in parallel (`--latexml-jobs`, default 4) and alongside marker; and the title check also reads the first few headings, because the PLATO mission paper (Rauer et al. 2025) prints 26,000 characters of consortium affiliations before its title.

Converted markdown goes to `plato_markdown/<bibcode>.md` plus `<bibcode>_images/`; whatever it replaces is moved to `plato_markdown_replaced/`. Raw downloads stay in `<data>/downloads/<bibcode>/`. The server may delete those, and the markdown too: the index keeps a paper's objects until its metadata changes, and then the paper is fetched again. marker runs in a Python of its own (`PLATO_MARKER_PYTHON`, else whichever runs `marker_single`), once per run for all PDFs so its models load once. OCR of ADS scans is slow: about four minutes for two pages on the Mac.

### Robustness and maintainablity

We'll need to monitor the chatbot, so we can fix it if something breaks, e.g. with PM2 and UpTimeRobot.

We rely on the LLMs from the university's AI Lab. If they change the version they serve, our chatbot breaks.

We may want to switch out Weaviate against Postgress with pgvector, as the latter as less likely to disappear without a clear alternative. Similarly we should review where else we rely on non-standard packages that might become a problem for maintenace in the coming decade or so.

For LLM observability we use LangFuse, but this may also be a risky dependency. Since 2026-09-29 the code does not depend on it: `platochat/tracing.py` records the spans through OpenTelemetry and sends them over OTLP to whatever backend `.env` names -- Langfuse (derived from the `LANGFUSE_*` keys), Arize Phoenix, Grafana Tempo, Jaeger -- or nowhere. Each span carries both OpenInference attributes (`input.value`, `openinference.span.kind`; Phoenix) and the OpenTelemetry GenAI ones (`gen_ai.request.model`, `gen_ai.usage.*`; how Langfuse tells an LLM call from other steps). Checked against the local Langfuse: same trace tree as before, with model and token counts. Whichever backend, the traces hold what the public typed, so it needs a retention period.
